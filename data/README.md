# NeoGuard data strategy

## Public research evidence

A useful published neonatal sepsis prediction resource is the Masino et al. PLOS ONE study:

https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0212665

The study describes 375 sepsis case episodes and 1,100 control episodes from NICU EHR data and evaluates multiple machine-learning models.

Associated code/data repository:

https://github.com/chop-dbhi/sepsis_01

Use the source according to its stated terms and provenance. Do not upload identifiable patient data.

## Current application model

The runnable application intentionally uses synthetic demonstration data generated by `ml/train_demo.py`.

This is deliberate: it allows the UI and software architecture to work without pretending that an online research dataset has already been cleaned, harmonized, ethically approved, or clinically validated for NeoGuard.

## Recommended real-data pipeline

1. Obtain the dataset under its permitted terms.
2. Document provenance and license.
3. Map source variables to the NeoGuard feature dictionary.
4. Remove direct identifiers.
5. Define the clinical outcome before looking at model performance.
6. Split at patient level to avoid leakage.
7. Prefer temporal or external validation where possible.
8. Compare baseline logistic regression with tree-based models.
9. Calibrate probabilities.
10. Measure sensitivity, specificity, PPV, NPV, AUROC, AUPRC and Brier score.
11. Test missing-data behavior.
12. Perform subgroup analysis.
13. Freeze the model version.
14. Validate prospectively before clinical deployment.
